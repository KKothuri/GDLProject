# Faster OpenVLA on LIBERO with speculative decoding

Course project. We try to speed up OpenVLA-7B on the LIBERO benchmark with speculative decoding, and to design a
better rule for accepting draft tokens. Baselines: plain OpenVLA, Spec-VLA (exact and relaxed acceptance), and KERV.
See `CLAUDE.md` for the plan, timeline and related work, and `results/SUMMARY.md` for the current numbers.

## Setup

Linux + NVIDIA GPU with at least 40 GB free (we use A40s; OpenVLA in bf16 needs ~16 GB, but the jobs check for 40).

```bash
git clone <this repo> gdl_proj && cd gdl_proj
bash setup.sh          # clones third_party/ at pinned commits, applies patches/, builds .venv, downloads models
source env.sh          # do this in every shell and job
```

`env.sh` points every cache (Hugging Face, pip, uv, torch, triton, wandb, LIBERO config, tmp) into this folder, so
deleting the folder removes everything. It also sets `MUJOCO_GL=egl` for headless rendering.

The Spec-VLA drafter weights are on Google Drive (links in `third_party/SpecVLA/README.md`). Put each one in
`checkpoints/specvla_drafters/libero_<suite>/` (`config.json` + `pytorch_model.bin`). KERV ships no weights; its drafter
has the same architecture, so we use the Spec-VLA drafters for it too.

Package pins that matter (newer versions break the eval): torch 2.2.0+cu121, transformers 4.40.1, flash-attn 2.5.5,
mujoco 3.2.3, tensorflow-metadata 1.14.0, wandb 0.16.6. Full list: `requirements.lock.txt`.

Raw per-episode results (~1 GB, with rollout videos) are not in git. They are on the SkyNet cluster at
`/coc/testnvme/skothuri7/repos/gdl_proj/results/`.

### Third-party patches

- `openvla`: `run_libero_eval.py` gets `--task_id` so each job runs one task.
- `KERV`: `--task_id`; per-task output dir; standard episode caps (220/280/300/520, the release used shorter ones);
  `F.rms_norm` fallback for torch 2.2; `KERV_FORCE_KF_EVERY` env var (default 4 = released behavior, 0 = never
  replace the model's action with the Kalman prediction).
- `LIBERO`, `SpecVLA`: unchanged. (No need to fork LIBERO; we do not modify it.)

## Running experiments (SLURM)

All job scripts are submitted from the project root. Array index = suite*10 + task (suites: spatial, object, goal,
10). Each job runs one task with 50 trials and aborts if the GPU has < 40 GB free (shared nodes).

| What | Command | Output |
|---|---|---|
| OpenVLA baseline | `sbatch scripts/libero_baseline.sbatch` | `results/baseline_openvla/` |
| Spec-VLA | `MODE=spec\|relaxed\|ar R=9 sbatch scripts/specvla_eval.sbatch` | `results/specvla/<mode>/` |
| KERV | `sbatch scripts/kerv_eval.sbatch` (`OUT_TAG=_noKF KERV_FORCE_KF_EVERY=0` for the variant) | `results/kerv*/` |
| Same-GPU latency, all methods | `sbatch scripts/latency_bench.sbatch` | `results/latency/` |
| Phase timing (vision/prefill/verify/draft) | see header of `scripts/profile_phases.sh` | `results/profile/` |
| Fair AR timing (stock HF generate) | `sbatch scripts/ar_timing.sbatch` | `results/ar_timing/` |

`scripts/specvla_eval.py` options: `--profile True` (CUDA-synced phase times), `--log_detail True` (every draft token,
the verifier's choice and confidence, gripper contact; used for error analysis). `specvla_eval.sbatch` passes extra
flags through `EXTRA_ARGS` and writes under `OUT_ROOT`.

Analysis (CPU only): `scripts/latency_summary.py` (`STAT=mean` or median), `scripts/analyze_accept.py`,
`scripts/analyze_drift.py`, `scripts/sim_rules.py` (offline speed estimate for stricter acceptance rules),
`scripts/aggregate_baseline.py`, `scripts/summarize_results.py`.

Cluster etiquette: the kira-lab A40s are shared. Throttle arrays (`%N`, or `scontrol update JobId=<id>
ArrayTaskThrottle=N`); we keep our total at 4 GPUs or fewer.

## Findings so far (details in results/SUMMARY.md)

- OpenVLA baseline reproduces the paper within 1-4.5 points per suite.
- Spec-VLA acceptance lengths match the paper, but the speedups do not: on one A40, exact is ~1.0x and relaxed (r=9)
  ~1.2x against Spec-VLA's own AR loop. That loop makes 8 LLM calls for 7 action tokens; stock HF generate makes 7
  (283 vs 315 ms/step). Against the fair baseline, relaxed r=9 is only ~1.1x.
- ~92 ms per step (vision + prompt prefill) cannot be sped up by speculative decoding; the drafter costs ~38 ms.
- KERV's extra speed comes from replacing the model's action with a Kalman prediction every 4th step, which costs
  14-25 points of success. With that off, KERV performs like Spec-VLA r=9.
- Relaxed acceptance mostly accepts draft tokens the verifier gives < 0.001 probability (verifier itself ~95% sure).
  Per-token signals (contact, confidence, drift) do not separate failed from successful episodes.
